# درس ۴ — صفحه‌های پروژه، داده‌ی typed و یک باگ واقعی

## شروع

```bash
cd ~/Portfolio && git pull && pnpm install && pnpm dev
```

بعد این صفحه‌ها را ببین: `/projets`، `/projets/portfolio` و یک آدرس اشتباه مثل `/projets/test`.

## نقشه‌ی فایل‌ها

```
src/content/projects/schema.ts    ← «قرارداد»: هر پروژه باید چه شکلی باشد (Zod)
src/content/projects/portfolio.ts ← داده‌ی واقعی اولین پروژه
src/lib/projects.ts               ← خواندن و اعتبارسنجی، فقط سمت سرور
src/components/projects/          ← card، badge وضعیت، لیست تکنولوژی
src/app/projets/page.tsx          ← لیست پروژه‌ها
src/app/projets/[slug]/page.tsx   ← یک route برای همه‌ی پروژه‌ها
```

## ۵ مفهوم کلیدی

### ۱. Zod: TypeScript در زمان اجرا

TypeScript فقط **موقع نوشتن کد** چک می‌کند و بعد از build از بین می‌رود. Zod **موقع اجرا** داده را چک می‌کند.

```ts
z.url({ protocol: /^https$/ }); // لینک http:// یا javascript: رد می‌شود
summary: text.max(180); // خلاصه‌ی طولانی رد می‌شود
```

یک قانون ترکیبی هم داریم: **پروژه‌ای که `status: "live"` دارد، باید لینک live داشته باشد.** یعنی سیستم نمی‌گذارد بدون مدرک ادعای «در حال اجرا» بکنی.
`projectSchema.parse()` موقع build اجرا می‌شود. داده‌ی خراب = **build شکست می‌خورد** و هیچ صفحه‌ی خرابی به production نمی‌رسد.

### ۲. `satisfies` در برابر type annotation

```ts
export const portfolio = { ... } satisfies Project;
```

`satisfies` شکل داده را چک می‌کند، ولی **نوع دقیق** آن را نگه می‌دارد. مثلاً `status` به‌جای `string` همان `"in-progress"` باقی می‌ماند.

### ۳. Route داینامیک: یک فایل برای N پروژه

`[slug]` یعنی «هر چیزی در این قسمت URL».
`generateStaticParams()` لیست slugها را به Next می‌دهد تا **همه‌ی صفحه‌ها موقع build ساخته شوند**. در خروجی build این را می‌بینی:

```
└   /projets/[slug]
  └ ○ /projets/portfolio   ← از قبل ساخته شده
```

برای پروژه‌ی دوم فقط **یک فایل داده** اضافه می‌کنی. هیچ صفحه‌ی جدیدی لازم نیست.

### ۴. کارت قابل‌کلیک با **یک** لینک

اشتباه رایج این است که کل کارت را داخل `<a>` بگذاری. صفحه‌خوان آن‌وقت کل متن کارت را به‌عنوان اسم لینک می‌خواند.
راه درست: فقط عنوان لینک است و `after:absolute after:inset-0` لایه‌ی نامرئی‌اش را روی کل کارت پهن می‌کند.
Focus ring هم با `has-[a:focus-visible]` روی کل کارت کشیده می‌شود.

### ۵. باگ واقعی: «soft 404»

آدرس `/projets/test` صفحه‌ی 404 را نشان می‌دهد، ولی **کد HTTP آن 200 است.** این را با `curl` پیدا کردم، نه با چشم.
**چرا؟** با Cache Components، Next.js اول پوسته‌ی ثابت صفحه (header و footer) را می‌فرستد. وقتی کد HTTP ارسال شد، دیگر نمی‌شود عوضش کرد.
**پیامدش چیست؟** Next.js خودکار `<meta name="robots" content="noindex">` اضافه می‌کند. پس Google این صفحه را index نمی‌کند. این را هم تست کردم.
**چرا درستش نکردم؟** راه‌حل یک Proxy بود که لیست پروژه‌ها را **تکراری** نگه دارد. دو منبع حقیقت = باگ آینده. مستندات Next.js هم توصیه می‌کند Proxy به ماژول‌های مشترک وابسته نباشد.
تصمیم گرفتم مستندش کنم (`README.md` بخش Known limitations) و رد شوم. **این هم مهندسی است:** همه‌ی باگ‌ها ارزش رفع کردن ندارند، ولی همه‌شان ارزش مستند شدن دارند.

## یک اصلاح صداقت

قانون این پروژه: **هر جمله‌ای در سایت باید با repo قابل اثبات باشد.**

## تمرین‌ها

**۱. خراب کن (عمدی):** در `portfolio.ts` مقدار `status` را `"live"` کن و `pnpm build` بزن. پیام خطا چه می‌گوید؟ بعد برگردانش.

**۲. اضافه کن:** یک پروژه‌ی آزمایشی بساز (`src/content/projects/test.ts`) و در `sources` داخل `lib/projects.ts` اضافه‌اش کن. با `pnpm dev` ببین صفحه‌اش ساخته می‌شود. **commit نکن** و بعد پاکش کن.

**۳. بررسی کن:**

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/projets/test
curl -s http://127.0.0.1:3000/projets/test | grep -o '<meta name="robots"[^>]*>'
```

خروجی‌ها را بفرست و توضیح بده چرا کد 200 است.
